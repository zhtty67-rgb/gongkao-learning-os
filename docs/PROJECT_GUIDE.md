# 系统分工与学习流程

## 两个项目各做什么

公考学习系统负责题目、作答、计时、信心、错因、掌握度、复习、对话和个人笔记。Knowledge Hub 负责教材文档、解析、切片、知识结构、检索和出处。

学习系统是学习工作台，Hub 是资料室。资料室没有命中某个考点，不代表不能做题：工作台仍可展示题目原解析，AI 也可根据本题分析，但应说明没有教材依据。

知识树帮助定位考点，17 个正式 LearningSkill 用于稳定地追踪学习能力。知识树可以有很多节点，不能每增加一个节点就自动发明一个统计技能。

## 做题后发生什么

1. 选择答案与正式提交是两个动作。取题可能先建立待提交记录；这种记录不等于已经完成一次作答。
2. 提交后按标准答案判分，保存作答事实。题库答案后来纠正时，另存校准结果，保留原始选择与原判分。
3. 原解析用于对照题目；AI 复盘用于解释疑问、寻找错因或讨论其他解法。两者不互相覆盖。
4. AI 复盘围绕本次作答组织上下文；讲解与后续对话按作答关联保存。回看记录应恢复历史，避免重新自动追问。
5. 用户确认或修订错因后，保留更改历史。个人感悟另存笔记，便于跨题整理。

## 申论教师模型怎样判断

教师规则来自资料和案例提炼，用来塑造模型阅读材料、取舍信息和组织答案的方法。相似案例是参照，新题不需要先找到一模一样的案例才允许批改。

程序检查引用是否真实、来源是否属于当前教师、作答版本是否一致；结论是否合理仍由模型结合题目与材料判断，用户可提出异议。规则存在或引文核验通过，不等于诊断已经被证明正确。不同教师的规则和来源不能混用。

## 感悟和笔记存在哪里

- `/notes` 汇总个人笔记，可按模块、类型与关键词查找，新增或编辑感悟。
- 本题心得按题目及作答关联；考点笔记可关联知识节点。关联入口以当前页面为准，不能把接口支持等同于每个页面都已有编辑按钮。
- 复盘中的“收藏到笔记”保存所选消息及其来源，方便回到相应题目。
- 申论工作台的梳理笔记也出现在汇总中；这类记录回到申论工作台修改，避免复制出两份互不一致的笔记。
- 笔记属于个人学习数据，不改标准答案、原解析、掌握度或复习安排。多页面同时修改时，版本冲突会要求核对，避免静默覆盖。

数据保存在本机 SQLite 数据库中。刷新可以重新读取已保存内容；尚未保存的编辑不应视为已入库。GitHub 源码版本不包含个人笔记，换机器需同时恢复数据库、资产和配置。
